# Интерпретация результатов (Results Analysis)

После успешного завершения бенчмарка скрипт генерирует подробный отчёт в формате JSON. Этот файл содержит не только итоговый балл, но и детализацию по каждой задаче, что позволяет точно понять сильные и слабые стороны модели.

## 📂 Где искать отчет

Файл создается в директории `results/` в корне проекта:
```text
results/
└── benchmark_result.json
```
> **Важно:** Папка `results/` добавлена в `.gitignore`. Если вы хотите сохранить историю прогонов или сравнить модели позже, скопируйте файл вручную или переименуйте его (например, в `qwen_7b_result.json`).

## 📊 Структура JSON

Пример содержимого `benchmark_result.json`:

```json
{
  "model": "qwen2.5-coder-7b",
  "mode": "coding",
  "timestamp": "2026-04-29 15:30:00",
  "overall_score": 68.4,
  "breakdown": {
    "easy_avg": 86.2,
    "medium_avg": 61.5,
    "hard_avg": 42.0
  },
  "details": [
    {
      "id": 1,
      "name": "Python Sort",
      "score": 100.0,
      "time": 12.5,
      "feedback": "3/3 tests passed"
    },
    {
      "id": 7,
      "name": "C++ ThreadPool",
      "score": 40.0,
      "time": 145.2,
      "feedback": "RAII: ✅ | Priority: ❌"
    }
  ],
  "conclusion": "🟡 ХОРОШО (Требует мелких правок)\nПаттерны: Легкие=86.2% | Средние=61.5% | Сложные=42.0%\n⚠️ Слабое место: многопоточность."
}
```

### Ключевые поля
| Поле | Описание |
|------|----------|
| `model` | Название протестированной модели. |
| `overall_score` | **Итоговый балл (0–100)**. Рассчитывается как взвешенное среднее (сложные задачи весят больше). |
| `breakdown` | Средний балл по категориям сложности. Помогает понять, где модель «проседает». |
| `details` | Массив с результатами по каждой из 10 задач. Включает время выполнения (`time`) и фидбек валидатора (`feedback`). |
| `conclusion` | Автоматически сгенерированный текстовый вывод с рекомендациями. |

##  Анализ метрик

Как правильно читать результаты:

1.  **Низкий `easy_avg` (< 70%)**: Модель плохо следует простым инструкциям или имеет проблемы с базовым синтаксисом. Высокий риск галлюцинаций в повседневных задачах.
2.  **Высокий `easy_avg`, но низкий `hard_avg`**: Модель хороша как «автодополнение», но не справляется со сложной архитектурой или безопасностью.
3.  **Поле `time`**:
    *   **< 10 сек**: Отличная скорость (обычно 7B модели на GPU).
    *   **30–60 сек**: Нормальная скорость для CPU или тяжелых задач.
    *   **> 120 сек (и таймаут)**: Модель слишком медленная для интерактивного использования в таком конфиге.
4.  **Поле `feedback`**: Содержит конкретную причину потери баллов (например, `RAII: ❌`). Используйте его для отладки промптов.

## 🤖 Автоматизация (CI/CD)

Вы можете использовать JSON-отчёт для автоматической проверки качества модели в вашем пайплайне сборки.

### Пример с `jq` (Linux/macOS)
```bash
# Получить итоговый балл
SCORE=$(cat results/benchmark_result.json | jq .overall_score)

# Условие: если балл ниже 70, остановить сборку
if (( $(echo "$SCORE < 70.0" | bc -l) )); then
    echo "❌ Quality check failed: Score is $SCORE (Threshold: 70)"
    exit 1
else
    echo "✅ Quality check passed: Score is $SCORE"
fi
```

### Пример на Python
```python
import json

with open('results/benchmark_result.json') as f:
    data = json.load(f)

if data['overall_score'] >= 75:
    print("Model is production-ready.")
else:
    print(f"Model needs improvement (Score: {data['overall_score']})")
```

## 📈 Сравнение моделей

Чтобы сравнить две модели, запустите бенчмарк дважды, сохранив результаты под разными именами:

```bash
# 1. Прогон первой модели
python launcher.py
mv results/benchmark_result.json results/model_A.json

# 2. Прогон второй модели (через редактирование .env)
python launcher.py
mv results/benchmark_result.json results/model_B.json

# 3. Сравнение ключевых метрик
diff <(jq .overall_score results/model_A.json) <(jq .overall_score results/model_B.json)
```
